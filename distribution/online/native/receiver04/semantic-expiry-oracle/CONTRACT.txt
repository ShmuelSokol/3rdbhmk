Scope and meaning
-----------------
Integer ticks model monotonic raw-QPC-domain milliseconds. Exact 500ms boundaries
are intentional; no calls to QPC, pipes, sockets, threads, subprocesses or UE.
This is an independent oracle for authenticated, already-parsed semantic input,
not a packet parser, socket implementation, physics simulation or native adapter.
The two pawn tags exercise the shared policy for walker and dove; actual native
hook parity needs separate compilation and runtime evidence. Vector addition is
unclamped and unscaled to expose provenance; engine movement/rotation scaling,
inertia, collision and camera constraints are outside this model.

Concrete integration contract
-----------------------------
1. Authenticate/validate before the mailbox. Capacity one, immutable sequence,
   connection generation and exact controller/pawn ownership. Native weak handles
   must be checked; model owns one implicit controller and names pawn identity.
   Queueing is not success. No remote InputKey injection into shared accumulators.
2. Deadline=min(acceptQpc+0.5s, sessionEndQpc), never extended at dispatch/controller
   or consumer. Model assumes accept/dispatch coincide; actual socket accept time
   must be retained if parsing/dispatch happens later. Owner must add parser-delay
   cases against the native implementation. Held input expiry is independently
   min(original input receipt+2s, sessionEnd), not consumption time+2s.
3. Button effects: PostProcessInput is reached from paused TickPlayerInput too.
   Recheck authorization at the state-changing handler branch. P/M allowed paused;
   interact rejected. Existing void handlers may no-op: return explicit outcome.
   NoEffect is not an applied action. Native handler work after entry can stall.
4. Controller movement routing is not consumption. Keep remote vector separately;
   merge it only after fresh authorization in actual ConsumeInputVector, including
   walker and dove paths. Do not put remote contribution in pawn shared pending
   vector early. Look is one-shot, checked at UpdateRotation, not shared MouseX/Y.
5. Pause clears held/pending remote move/look even if normal PlayerTick is skipped;
   fresh P/M still works through paused input. Resume never replays discarded input.
   Release, disconnect, pawn replacement and generation change revoke pending/held
   remote state. Preserve local contributions. Completed effects cannot be undone.
6. Response becomes consumed/no_effect/paused_rejected/cancelled only after actual
   semantic processing with sequence and consumption timestamp. At the original
   response deadline host result is unknown even if internal result is known.
   A missing consumer yields pending then unknown, not success. A new command
   submitted explicitly later is allowed; no code automatically resubmits with
   the same OR a fresh sequence after uncertainty. Dedupe alone is insufficient.
7. Bound the host wait externally. A blocked game thread cannot cancel itself or
   send a timely rejection. Owned watchdog/process teardown remains required.
   Checks authorize entry at the consumer boundary, not a hard real-time guarantee
   that all effects finish before expiry. A stall inside the handler yields unknown
   to the caller and may have caused an effect. Never claim rollback from timeout.
