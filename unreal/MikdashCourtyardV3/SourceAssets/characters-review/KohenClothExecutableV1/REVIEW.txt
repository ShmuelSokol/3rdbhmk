Entry point and isolation
  ReviewProject/KohenClothReview.uproject is a NEW standalone project. No courtyard
  module, config, plugin enablement, production binding, asset or map is modified.
  run_in_editor.py imports hash-pinned WalkV2 and combined GLBs into a fresh namespace,
  with material/physics imports disabled and animation sampling explicitly60Hz.
  A fresh skeleton is created from the unchanged source rig; the combined mesh uses it.
  C++ duplicates the combined mesh transiently and changes only its KG_Meil clothing.
  No asset is saved. Original input asset/GLB hashes are checked before/after execution.

Implemented C++ (ReviewProject/Plugins/KohenClothExecutable/.../Private)
  KohenClothBuilder.cpp constructs modern managed cloth collection with six separate
  physical patterns: Meil836 dynamic/pinned-upper vertices, Ketonet and both shin/foot
  meshes10504 kinematic vertices. It seeds Chaos config and explicitly enables
  SelfCollideAgainstAllKinematicVertices in the SAME physical model.
  RenderDeformer optional schema is explicitly defined. Native KG_Meil render vertices
  retain exact positions/order, bone weights, material and section topology. Mapping
  generation supplies an outer-triangle-only filter. Rest position, normal-tip and
  tangent-tip reconstruction must all be within0.01cm. Bone-axis fit must be unique
  within0.05cm. No hardcoded native section ID, guessed axis or collider mapping.
  Build validates physical vertex/triangle order. Binding validates the actual result,
  including every influence index, blend and barycentric value. No reliance on the
  binding bool alone. All other sections, materials, rig and source remain identical.

  KohenClothWalk.cpp uses a private FPreviewScene and synchronous
  FClothingSimulationInstance FillContextAndPrepareTick/Simulate/AppendSimulationData.
  It does not tick a production world. Fixed config:nominal5/max5 adaptive iterations,0.5cm self-contact
  thickness,0.1 bending stiffness,zero animation drive,gravity980.665cm/s2, no sweep.
  Settles120 steps then records288 walk samples at240Hz, from0 to287/240 seconds.
  Data.Transform is applied before converting component positions to author axes.
  Every fixed particle must match independently skinned posed rig within0.05cm.
  Each atomic f32 frame contains solver particles, mapped outer render vertices,
  unchanged skinned outer control and27 bone positions. Atomic progress every24 frames.
  Partial frames survive failure; no cleanup deletes evidence. Five-minute simulation
  budget is checked between steps (not a preemptive native-process timeout).

Control interpretation and eventual two-layer cloth
  OUTER-ONLY IS API FEASIBILITY, NEVER THE FINAL DRAPE SOLUTION. The exact rigid-skinned
  ketonet retains ankle-following deformation and may force the outer shell into the
  same shelf through contact. A persistent shelf here cannot falsify cloth as a fix.
  The per-frame skinned outer control distinguishes solver response from the original
  affine motion, while exact inner readback exposes the obstructing shape.
  Both layers already occupy distinct indexed patterns of one physical collection;
  body obstacles remain separate zero-distance patterns. A later reviewed change can
  make ketonet below its upper pins dynamic, retain body colliders, and add a separately
  filtered inner render pattern. This requires garment-part extraction from KG_Linen:
  that material ALSO includes the turban, so binding the entire section is prohibited.
  Current entry point deliberately refuses a second dynamic layer until that separate
  mapping/extraction review. No runtime switch secretly enables a second candidate.
  Bells/pomegranates stay skinned in this shell proof. They require later garment-only
  attachment work before judging the complete period silhouette. Face/hair/turban and
  the original rig are never replaced or simulated.

  SourceAssets/context-review/HaramThresholdSidesV1/native-slot-blocked.json relative

  Only confirmed owned cleanup permits removal of this run's matching sentinel.
  Unconfirmed/unknown cleanup, including constructor failure, leaves it in place
