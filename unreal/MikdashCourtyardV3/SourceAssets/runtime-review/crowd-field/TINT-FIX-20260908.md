# Crowd tint fix — 8 September 2026

Defect: the instanced crowd (`RELEASE_CrowdField`, six HISMs) rendered as uniform grey figures in
`SourceAssets/visual-review/release-capture-20260908T203956Z/c_outer_court_pilgrims.png`.

## Confirmed cause (evidence, not assumption)

Read-only dump receipt: `tint-dump-dump-20260908T213249703381Z.json` (log `C:\Mikdash\Working-5.8\Fable-CrowdTint-Dump-01.log`; map hash unchanged, `mapBytesChanged: false`).

| Candidate | Result |
|---|---|
| (a) NumCustomDataFloats never set | **Ruled out.** All six `CrowdPose0..5` read `num_custom_data_floats = 3` from the saved map and after an in-memory `BuildEditorPreview`. Saved custom data length = 3 x instances on every component. |
| (b) material does not read PerInstanceCustomData | **Ruled out.** `M_CrowdRobeV1` BaseColor input is a `LinearInterpolate` whose Alpha is `PerInstanceCustomData(data_index=1)`; a second node reads index 0 for the WPO bob. |
| (c) grey placeholder material on the HISMs | **Ruled out.** Every slot resolves to `/Game/MikdashV3/Runtime/CrowdFieldV1/Materials/M_CrowdRobeV1`; no component overrides; `CrowdMaterialOverride` unset. The real-RHI capture log has no compile failure or usage-flag fallback. |
| (d) index mismatch C++ vs material | **Ruled out.** C++ writes channel 0 phase, 1 tint, 2 standing; saved channel 1 holds exactly {0, .25, .5, .75, 1} at roughly 20 % each (5 distinct values per HISM); channel 2 is 0/1. The material reads index 1. |

Actual cause, two parts:

1. **The authored palette was grey.** The V1 robe material lerps between `[0.62, 0.58, 0.52]` (light stone linen) and `[0.29, 0.26, 0.30]` (dark grey-purple wool). Five steps between two near-neutral colours are five shades of grey; the channel worked and delivered exactly that.
2. **Every one of the 15 mesh slots carried the robe material**, including face, hands, neck, head cover and sash. The OBJ importer named the slots `<Group>Mat` (`FootMat`, `HeadMat`, `SashMat`, ...), so `release_crowd_field.py`'s matcher (which looked for the words `skin`/`wrap`) fell through to `CrowdRobe` for all 15 and recorded them as `_unmatchedMaterials`. With no skin tone or light head cover there was nothing to break the grey silhouette.

Not a C++ defect. `Private/MikdashCrowdField.cpp` and `Public/MikdashCrowdField.h` were **not** edited.
