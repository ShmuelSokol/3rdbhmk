# Runtime dependencies for the 48 cm architecture candidate

Audit by Astra, 2026-09-08. This is an implementation inventory, not a completed migration. The later implementation update below supersedes the audit's source-only status for the descriptor and cinematic intro; no map, native asset or active default was changed by this worker. Read `AMAH-MIGRATION-PLAN.md` first. The selected architectural unit is 48 cm; the main map remains legacy 50 until its coherent replacement passes native checks.

## The immediate blockers

Scaling the placed actors is insufficient. The cinematic subsystem builds its own legacy path; the resident JSON parser enforces legacy floor heights and bounds; the service scheduler enforces legacy sanctuary boundaries; FX initializes additional non-reflected room extents in its constructor. These would remain wrong in a map with correctly resized architecture. Save restore currently teleports stored centimetres without a scene-unit compatibility check. Do not promote the partial architecture candidate or merely replace the global 50 constants.

The safest compatibility contract is an explicit **world-scoped scene descriptor** with an immutable scene revision, architectural unit (Legacy50 or Selected48), confirmed origin, and coordinate-data revision. Resolve it before runtime consumers start. Unmarked existing worlds use Legacy50; a reviewed candidate must carry Selected48 explicitly. Never infer the unit from a filename substring or a coordinate's magnitude, and never put the selected unit in a process-global mutable variable: two editor worlds can coexist, and GameInstance subsystems survive map changes. This descriptor does not exist yet.

There are two separate data paths:

- Saved actor properties in the candidate are migrated once offline and marked as candidate-native coordinates. Runtime must not scale these a second time.
- Legacy source JSON or constructor fallback coordinates are decoded into a temporary world-specific representation once. Keep immutable legacy input and reject mismatched revision metadata. Alternatively provide separately staged candidate48 JSON and set only the candidate actor's path; never switch the global `DefaultGame.ini` path while the main map is legacy50.

`MikdashUnits.h` already provides legacy50/selected48 constants, `TryScaleLegacyArchitecturePoint`, `TryPlaceAboveMigratedFloor` and `TryPlaceAboveFloor`. It has no runtime consumers or world selection. Reuse its finite/transactional conversion rather than inventing another factor. Native X/Y/Z axes stay as recorded; crowd JSON and some source prose disagree on the verbal north/south label, so do not reinterpret numeric Y signs during this migration.
